# L2TPBridge — v1.0

نصاب تعاملی مستقل برای L2TPv3 over IP و فوروارد TCP/UDP با Xray روی ایران.
این بسته نسخه یا آپدیت TunnelForge نیست.

## نصب مستقیم از GitHub

روی هر دو سرور اجرا کنید (از پوشه‌ای که L2TPBridge داخلش وجود ندارد):

```bash
sudo apt-get update && sudo apt-get install -y git
git clone https://github.com/TIR3D4/L2TPBridge.git
cd L2TPBridge
sudo bash install.sh
```

نصب با دانلود bootstrap، بدون نیاز به git:

```bash
setup_dir=$(mktemp -d)
curl -fsSL https://raw.githubusercontent.com/TIR3D4/L2TPBridge/main/bootstrap.sh -o "$setup_dir/bootstrap.sh" && sudo bash "$setup_dir/bootstrap.sh"
```

برای این روش curl باید نصب باشد. bootstrap از شاخه main فایل‌های نصاب را دانلود می‌کند.

ابتدا روی خارج گزینه ۱، سپس روی ایران گزینه ۲ را انتخاب کنید.
در هر دو سرور IP واقعی ایران و خارج را یکسان وارد کنید.
IPهای تونل پیش‌فرض: ایران `10.10.10.1`، خارج `10.10.10.2`، ماسک `/30`.
اگر این محدوده با مسیرهای موجود تداخل داشت، یک محدوده خصوصی /30 دیگر انتخاب کنید؛ در هر دو سرور یکسان.

روی ایران پورت ورودی و پورت مقصد را وارد کنید، مثلاً ۲۰۵۳ و ۲۰۵۳.
پروتکل: `tcp` یا `udp` یا `tcp,udp`.
برای باز کردن دوباره منو:

```bash
sudo l2tpbridge
```

## پیش‌نیاز و تنظیم سرویس اصلی

- Debian/Ubuntu با systemd، دسترسی root و کرنل دارای ماژول‌های `l2tp_core`، `l2tp_ip` و `l2tp_eth`.
- IPv4 واقعی هر سرور باید روی همان سرور باشد؛ این نسخه NAT را پشتیبانی نمی‌کند.
- دسترسی مخازن apt لازم است. روی ایران دسترسی GitHub/API GitHub برای دانلود Xray لازم است.
- Xray در مسیر اختصاصی نصب می‌شود و SHA256 آرشیو با digest رسمی release تطبیق داده می‌شود. اگر digest موجود نباشد نصب متوقف می‌شود.
- پروتکل **IP شماره 115** بین دو IP واقعی در فایروال سیستم و دیتاسنتر باید مجاز باشد. این TCP یا UDP پورت 115 نیست.
- پورت‌های ورودی انتخاب‌شده روی ایران باید در فایروال مجاز باشند.
- سرویس اصلی روی خارج باید روی IP تونل خارج یا `0.0.0.0` گوش دهد و اتصال از IP تونلی ایران به پورت مقصد مجاز باشد. سرویس فقط روی `127.0.0.1` از این مسیر قابل دسترسی نیست. برای Docker نیز publish/bind پورت را بررسی کنید.
- فایروال خودکار تغییر نمی‌کند؛ هیچ flush یا جایگزینی قوانین انجام نمی‌شود.
- L2TPv3 به‌تنهایی رمزنگاری ندارد؛ رمزنگاری سرویس اصلی حفظ می‌شود. فوروارد Xray آدرس مبدأ کاربر را به سرویس اصلی منتقل نمی‌کند.
- آدرس IP یا دامنه اتصال کاربر باید به ایران اشاره کند. در کانفیگ TLS/Reality مقادیر SNI، کلیدها و مشخصات سرویس اصلی را نگه دارید.

## ماندگاری و محدودیت‌ها

تونل و فوروارد با systemd در بوت فعال می‌شوند. سرویس Xray در صورت خروج با خطا دوباره اجرا می‌شود؛ ساخت تونل ناموفق نیز دوباره تلاش می‌شود. این نسخه مانیتور خودکار قطعی مسیر یا تضمین پایداری ارتباط ایران/خارج ندارد.

اینترفیس اختصاصی: `lb-l2tp0`؛ Tunnel ID ایران/خارج: `61001/61002`؛ Session ID: `62001/62002`.
اگر ID یا اینترفیس موجود باشد، نصب متوقف می‌شود و آن را حذف نمی‌کند.
این نسخه یک جفت سرور و چند پورت فوروارد را مدیریت می‌کند.

فایل تنظیمات: `/etc/l2tpbridge/state.json` و `/etc/l2tpbridge/xray.json`.
نام سرویس‌ها: `l2tpbridge-tunnel.service` و `l2tpbridge-xray.service`.
برای تغییر endpointها از گزینه حذف نصب و تنظیم دوباره استفاده کنید.
نصب مجدد روی پیکربندی موجود آن را بازنویسی نمی‌کند.

## تست

گزینه ۶ تست پینگ و اتصال TCP به مقصد خارج و listener محلی را اجرا می‌کند.
پینگ موفق به معنی کارکرد کامل کانفیگ نیست؛ اتصال TCP به listener محلی نیز به تنهایی عبور داده را ثابت نمی‌کند.
UDP به درخواست/پاسخ واقعی برنامه نیاز دارد. تست نهایی را با کانفیگ واقعی کاربر از خارج سرور انجام دهید.

روی خارج بررسی کنید:

```bash
sudo ss -lntup
sudo l2tpbridge test
```

اگر پینگ برقرار نشد، تنظیم دو سرور، protocol 115 در مسیر و ماژول کرنل را بررسی کنید.
اگر پینگ برقرار بود ولی مقصد TCP باز نشد، bind پورت سرویس خارج و فایروال را بررسی کنید.
اگر دیتا عبور می‌کند ولی بعضی اتصال‌ها گیر می‌کنند، هنگام تنظیم مجدد MTU پایین‌تر مانند ۱۳۶۰ را امتحان کنید.

## اعتبارسنجی این بسته

هشت تست آفلاین موفق: IDهای متقابل، اعتبارسنجی IP/ساب‌نت و پورت، مقصد فوروارد، پاکسازی ساخت ناقص و بازگردانی کانفیگ پس از خطای Xray/restart.
نحو Bash و Python بررسی شده است. دانلود و اجرای واقعی Xray، ساخت واقعی تونل و ریبوت دو سرور در محیط تحویل آزمایش نشده‌اند؛ این‌ها روی سرورهای شما باید تأیید شوند.

اجرای تست‌ها بدون تغییر سرور:

```bash
python3 -m unittest -v test_manager
```
